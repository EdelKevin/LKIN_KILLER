# resume-based-on-jd

A multi-agent resume tailoring pipeline. Takes a job description (LinkedIn URL or pasted text) and produces an ATS-friendly, single-page resume in PDF + DOCX, customized to the JD's required tech stack.

Built for **3year / Entry / New Grad / Intern SWE applications in North America**.

---

## What it does

```
Job description URL  ──►  Orchestrator
                              │
                              ├─► N Writer subagents (parallel, one per JD)
                              │       │
                              │       ├─ fetch JD
                              │       ├─ extract grep-able tech keywords
                              │       ├─ score P0 / P1 / P2 priority
                              │       ├─ check bullet bank (reuse pre-written variants)
                              │       ├─ tailor via Strategy A (swap) / B (embed) / C (augment)
                              │       └─ write tailored .md
                              │
                              ├─► N Reviewer subagents (fresh context, 17-item rubric)
                              │       └─ max 2 rounds, flag ⚠️ if persistent fail
                              │
                              └─► render .pdf + .docx, aggregate report
```

## Why this exists

Manually tailoring a resume for every JD is slow. ATS keyword filters reject resumes that don't match the JD's stack literally. This pipeline:

1. Extracts every grep-able tech keyword from a JD
2. Prioritizes them by signal (required vs preferred vs off-hand)
3. Injects them into coherent, context-appropriate bullet points in the existing resume
4. Maintains writing style fingerprint (verb voice, bullet pattern, single page)
5. Enforces strict NA-CS resume rules (verb compliance with seniority ceilings, ≤3 tech per bullet, no duplicate keywords, etc.)
6. Reviews each draft with an independent critic agent (Karpathy/harness-style)
7. **Caches pre-written tech bullet variants** — over time, the cache absorbs most common JD techs, reducing AI generation to near-zero

## Setup

### Prerequisites
- macOS, Linux, or Windows via WSL (uses Chrome/Edge headless for PDF rendering)
- Python 3.10+
- A Chromium-based browser — auto-detected in this order: macOS Chrome, Windows Chrome/Edge under `/mnt/c` (WSL), `google-chrome`/`chromium`/`chrome` on PATH. Override with the `CHROME_BIN` env var.
- Python packages:
  ```bash
  pip install python-docx markdown-it-py pypdf
  ```

### Install the pipeline
```bash
git clone git@github.com:<your-username>/resume-based-on-jd.git
cd resume-based-on-jd
```

### Phase 0 — bootstrap with your own resume

Before running per-JD tailoring, instantiate the pipeline with your resume:

1. Drop your resume PDF anywhere on disk
2. In a Claude Code session, say:
   > "Run Phase 0 on `<path-to-resume.pdf>`"
3. The agent will:
   - Parse your resume into `base_resume.md` (with `[REDACTED]` placeholders for PII)
   - Extract voice + structure fingerprint → `style_profile.md`
   - Build skill + business-problem inventory → `skill_inventory.md`
   - Reset `bullet_bank.md` to an empty skeleton

Full SOP: see [`phase_0.md`](./phase_0.md).

### Phase 1 — tailor per JD

1. Paste 1–10 LinkedIn job URLs (or other JD URLs / pasted text) to Claude Code
2. The orchestrator fans out writer + reviewer subagents in parallel (cap 5 per wave to avoid LinkedIn rate-limits)
3. Outputs land in `./outputs/{company}_{role_slug}_{YYYYMMDD}.{md,pdf,docx}`

## Architecture highlights

### Multi-agent pattern
- **Orchestrator** (main session) reads context bundle once, fans out subagents
- **Writer subagents** are general-purpose agents with isolated contexts — one per JD, no cross-contamination
- **Reviewer subagents** start with fresh context (haven't seen the writer's reasoning) and apply a strict 17-item rubric, returning structured pass/fail JSON
- Max 2 review rounds; on persistent failure the output is saved with `WARN_` prefix

### Bullet bank (cache-based generation)
Every time AI generates a new tech bullet variant, it's indexed in `bullet_bank.md` by tech name. Future runs check the bank first — only generate when not cached. Goal: phase out AI generation entirely once the bank covers the common-tech long tail.

### 17-item reviewer rubric
Covers:
1–8. P0/P1 coverage, bullet pattern, metric density, realistic scale, page count, hard-fact preservation, bold rule
9. Business-tech consistency (no Kafka in a frontend-UI bullet)
10. Number coherence (no contradictions across bullets)
11. ≤3 techs per bullet (split if more)
12. No duplicate tech across whole resume
13. Verb compliance (no `architected`/`designed`/`led` for NG)
14. Article cleanup (no unnecessary `the`/`a`/`an`)
15. Section title case (`Education` not `EDUCATION`)
16. Unified quantification cap (≤40%; >25% must name mechanism)
17. No ChatGPT footprints (no `phrase: detail` colon format)

## Hard constraints

- ✅ Locked facts (company names, job titles, dates, schools) NEVER modified
- ✅ Past-job locations NEVER modified — only header city swaps per JD
- ✅ Single page always
- ✅ Output English
- ❌ Never pauses mid-run to ask "did you actually do X?" — the candidate reviews every output and owns interview readiness for every claim
- ❌ Never auto-submits applications
- ❌ Never writes real PII (name, email) into the workdir — `[REDACTED]` placeholders only
